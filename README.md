# 果哥 · 水果店智能运营助手 MVP 3.0

一个面向中小生鲜水果店的对话式经营 Agent，围绕“订单为单一数据源”设计。老板导入订单与采购 CSV 或 Excel 后，可以通过多轮自然语言对话询问采购、定价、复盘和库存问题，并得到可执行的经营建议。

## 快速启动

### Windows 一键启动

双击 `run.bat`。浏览器会自动打开 `http://127.0.0.1:8501`。

### 命令行启动

```bash
pip install -r requirements.txt
python app.py
```

如果 8501 端口被占用，服务会自动顺延到下一个可用端口。启动成功后终端会打印实际地址。

本机还带有 Codex 工作区运行时，可以直接使用：

```powershell
& "C:\Users\15724\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe" app.py
```

## 5 分钟演示路径

1. **对话工作台**：点击“明天该进什么货？”，查看采购建议。回答里会同时给出预算、SKU 数、重点商品和不确定性说明。
2. **明日采购**：进入采购页，调整某个商品的采购量，勾选/取消 SKU，点击“确认采购单”。此操作会写入经营任务状态。
3. **动态定价**：查看临期风险分层、折扣窗口、预计回收金额，并执行折扣方案。
4. **经营复盘**：切换日报/周报，查看自然语言复盘、销售趋势、利润贡献和下一步动作。
5. **数据中心**：查看订单明细、采购明细和库存，修改 SKU 信息；也可以替换为自己的 CSV 或 Excel，或清除全部数据重新开始。
6. **门店记忆**：新增一条老板经验，或在对话里说“记住，雨天西瓜少进 20%”，观察它被沉淀为结构化记忆。

## 已实现的 MVP 能力

### 1. 明日采购建议

- 使用近 7 天订单计算真实动销，而不是用进货量倒推销量。
- 叠加天气、周末客流、商品趋势、货架期和门店经验。
- 输出建议采购量、预算、置信度和可解释的判断依据。
- 短保商品自动降低安全库存天数。

### 2. 动态定价建议

- 用“剩余可售天数 / 货架期”判断临期风险。
- 按风险分层给出 7 折、8 折、8.5 折等建议，而不是统一打折。
- 老板可以在定价页设置最低折扣，系统建议不会低于该折扣。
- 同时给出执行时间、组合装、预计回收现金和减少损耗。
- 支持生成会员触达文案。

### 3. 每日 / 每周经营复盘

- 聚合销售额、订单数、客单价、毛利率、商品贡献和损耗风险。
- 先由确定性计算层得出结论，再由语言层组织成老板能直接读懂的表达。
- 每条复盘都带下一步动作，避免“只描述、不决策”。

### 4. CSV / Excel 数据管理与库存计算

- 支持订单明细和每日采购记录两类文件，兼容 `.csv` 与 `.xlsx`。
- 自动识别中英文列名、匹配商品、按“单号 + 商品 + 数量 + 单价”去重。
- 重新计算库存、近 7 天销量、可售天数、毛利和风险等级。
- 提供订单模板、采购模板、CSV 模拟数据和库存导出。
- 支持一键清除全部经营数据，门店记忆会保留。
- 数据工作区可查看订单明细、采购明细、全部流水分页和 SKU 信息，并直接修改 SKU。

### 5. 门店专属记忆

- 对话中识别“记住 / 以后 / 经验”等表达，自动沉淀为结构化记忆。
- 记忆包含标签、来源、作用范围和生效状态。
- 支持手动新增、停用、删除，并在采购和定价中引用。

## 数据规则与默认假设

### 订单明细必填列

`日期`、`订单号`、`商品编码` 或 `商品名称`、`数量`

推荐补充：`单价`、`销售额`、`支付方式`、`时段`

### 每日采购记录必填列

`日期`、`采购单号`、`商品编码` 或 `商品名称`、`采购数量`

推荐补充：`采购单价`、`采购金额`、`供应商`

### 库存与预测

MVP 使用可解释的滚动窗口规则：

```text
当前库存 ≈ 1.2 天期初库存 + 近 3 天采购 − 近 3 天销售
明日预估销量 = 近 7 天日均销量 × 周末系数 × 天气系数 × 趋势系数
建议采购量 = 明日预估销量 × 安全天数 − 当前库存
可售天数 = 当前库存 / 近 7 天日均销量
损耗风险 = 可售天数 / 货架期 + 短保与下滑趋势修正
```

这样做的目的不是追求最复杂的预测模型，而是先验证产品闭环，并保证面试演示时每一个数字都能解释。接入真实门店后，应把期初库存、损耗单、盘点单和批次效期纳入数据源。

## 产品架构

```text
交互层
  对话工作台 / 采购页 / 定价页 / 复盘页 / 数据中心 / 门店记忆
        ↓
Agent 编排层
  意图识别 → 选择工具 → 读取门店记忆 → 组织自然语言 → 记录决策
        ↓
工具层
  calculate_inventory
  forecast_demand
  recommend_purchase
  score_freshness_risk
  recommend_discount
  summarize_period
  upsert_store_memory
        ↓
数据层
  订单明细 + 采购记录 + 商品目录 + 门店记忆 + 经营任务
```

关键设计原则：**大模型负责表达和解释，业务计算由确定性工具完成。** 这样既能保持自然语言体验，又能避免模型在库存、金额和采购量上“编数字”。

## 真实大模型与实时天气

MVP 3.0 会自动检测 `DEEPSEEK_API_KEY` 并接入 DeepSeek 对话模型；也支持 OpenAI 兼容接口。启动时会检测连接状态，对话工作台右侧会显示模型、响应延迟和实时天气来源。

日销、库存、采购量、价格和折扣仍然由本地经营工具计算，大模型负责经营解释、对话表达和每日/每周复盘文字。若网络或模型不可用，会自动回退到本地规则，不影响门店基本操作。

可配置环境变量：

```powershell
$env:DEEPSEEK_API_KEY="your-key"
# 可选覆盖：
$env:GZ_LLM_BASE_URL="https://api.deepseek.com"
$env:GZ_LLM_MODEL="deepseek-chat"
python app.py
```

也可以复制 `.env.example` 为 `.env` 后填写。

天气数据通过 Open-Meteo 实时获取。默认门店坐标为上海，可通过 `GZ_STORE_LAT`、`GZ_STORE_LON` 和 `GZ_STORE_CITY` 修改。

## 当前边界与下一步

MVP 暂不包含登录、多门店、真实 POS 对接、批次效期、损耗单、支付和消息推送。下一版优先补三件事：

1. **损耗与盘点数据**：把“预估损耗”升级为真实库存校准。
2. **门店经营日志**：记录采购、折扣、断货、活动等动作，形成“建议 → 执行 → 结果”的闭环评估。
3. **个性化预测**：在规则基线之上加入门店级时序模型，并用真实损耗率持续校准。

## 面试时可强调的产品判断

- 目标用户不是大型连锁，而是没有 ERP、靠老板经验的社区水果店；核心约束是“低录入成本”和“建议必须可执行”。
- 订单是单一事实源，避免同时维护多个互相矛盾的库存数字。
- 生鲜的核心不是“卖得越多越好”，而是“在货架期内卖掉”；因此采购和定价必须共享同一套时效风险。
- 自然语言只是交互层，库存与采购量必须有可解释的计算层，否则老板不会信任。
- 门店记忆要结构化，才能真正改变计算结果；仅仅把老板的话塞进提示词，无法形成稳定产品能力。
